## 修复 "Release of invalid GC handle. The handle is from a previous domain"

原生堆栈指向 `UploadHandlerRaw::~UploadHandlerRaw` ← `UnityWebRequestAsyncOperation::InvokeCoroutine`：
脚本热重载时，带上传体的 UnityWebRequest 没被释放，等到新域里完成，原生层去释放旧域 GCHandle 就报这句。

全工程唯一的 `UploadHandlerRaw` 在 `TikTokPlatform.SendConversionRequest()`（巨量引擎转化回传 POST）。
改法（`Assets/AdSDK/Scripts/TikTokPlatform.cs`）：
- `SendConversionRequest` / `SendOpenIdLog` 加 `#if UNITY_EDITOR` 短路：编辑器里没有真实 clickid/登录态，直接跳过 + 回调 false，不再发请求
- 新增「网络请求兜底清理」区：编辑器下用静态表登记在途请求，`AssemblyReloadEvents.beforeAssemblyReload` 里统一 `Abort()` + `Dispose()`
- 两个协程改成 `try { yield return www.SendWebRequest(); } finally { Untrack + Dispose }`，去掉 `using var` 跨 yield 的写法

注意：
- 该告警是编辑器专属的原生提示，不影响真机包，`skipped` 只是少释放一个句柄
- `ttsdk.dll` / `ttsdk_tools.dll` 里也各有一处 `UploadHandlerRaw`（预编译包，无法改），如果只在启动时偶发一次，属于 SDK 自身的在途请求，可忽略
- 日志里 `AssetDatabase.FindAssets: Folder not found: 'Assets/ByteGame'` 是 bgdt 扫描旧路径的告警，同级两个抖音工程也一样，无害
- `%LOCALAPPDATA%\Unity\Editor\Editor.log` 被本机多个 Unity 实例共用，读日志时注意混入其他工程的行
